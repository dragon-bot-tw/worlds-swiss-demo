# Design

## Context

見 `proposal.md` 的 Why。專案沒有既有前端或伺服器，只有 OpenSpec 骨架。行為契約在 `specs/swiss-snapshot/spec.md` 與 `specs/advance-trial/spec.md`。

官方 `getSchedule` 的最新一頁同時含有 2025 與 2026 的「瑞士制循環賽」。隊伍上的 `record` 是抓取當下的總戰績，不是該場開打前的戰績。第五輪在賽程裡是 TBD 對 TBD。

## Goals / Non-Goals

**Goals:**

- 試算結果只由快照與使用者操作順序決定，重放得到同一張對戰圖。
- 走向的未消耗步驟在下一輪配出後自動寫入該隊的新場次。
- 頁面是一張轉播式對戰圖加一個局面板，技術上只用 HTML、CSS 與原生 JS。

**Non-Goals:**

- 執行期同步賽程、八強對手抽籤、局數差計分、前端框架與打包。

## Decisions

### 快照在建置時抓一次，執行期只讀檔

製作快照的腳本請求 `getSchedule?hl=zh-TW&leagueId=98767975604431411`。API key 由執行該腳本時的環境變數讀入，不寫進 JSON、頁面或伺服器。腳本只保留 2026 年、`blockName` 為「瑞士制循環賽」、兩邊都是實際隊伍代碼的場次，勝者取 `outcome === "win"` 的代碼，丟棄 `record` 與 TBD 場次。

賽區與種子不在這支 API 裡，腳本以固定對照併入隊伍：LCK 為 GEN、HLE、T1、DK；LPL 為 AL、BLG、TES、IG；LEC 為 G2、MKOI、KC；LCS 為 TLAW、LYON；LCP 為 TSW、CFO；CBLOL 為 LOS。種子依該賽區順序為 1 起算。

JSON 至少包含 `fetchedAt`、隊伍的 `code`、`name`、`region`、`seed`，以及每場的 `id`、`startTime`、兩邊代碼與 `winner`。

替代方案是頁面每次開啟都打 API。這會讓已結束場次的邊界隨時間變動，也要把 key 放到用戶端，因此不採用。

### 試算是一份可重放的操作紀錄

狀態等於快照加上依序的操作：套用走向、面板判勝、對調、清除。重算時從快照重放，不使用亂數，也不把 50/50 寫進勝者。

走向的每一步是該隊「下一場勝」或「下一場敗」，不記錄對手。能對上現有場次的步驟立刻寫入；寫不進去的留在該隊佇列。第四輪六場都有勝者後才產生第五輪，然後消化佇列。

同一場兩邊佇列矛盾時，保留操作序號較大的那一步，另一隊的剩餘佇列整段作廢。面板手動判勝會寫入該場，並作廢該隊剩餘佇列。對調先清掉被改寫兩場的試算勝者，再依仍在的佇列寫入新對戰。

替代方案是套用時只改已經畫出來的第一場，其餘等使用者再點。這與「整條記住、配出來就自動走」不符。

### 配對窮舉同戰績池

仍未三勝也未三敗、且戰績相同的隊伍構成一個池。人數為奇數時不配對並顯示無法配對。人數為偶數時列出全部完美匹配，依序比較：重賽數較少、同賽區數較少、隊伍代碼字典序較前。每一對先把兩隊代碼排序，再把所有對排序後比較。官方已經配好的第四輪沿用快照，不重配。

替代方案是模仿官方的隨機抽籤再加種子。同一組結果會得到不同對戰，無法重現。

### 頁面分成對戰圖與單一面板

`index.html`、`styles.css`、`app.js` 由 Node 內建 `http` 送出，不使用 Express，也不呼叫官方 API。對戰圖是 0-0 到 2-2 的五欄漏斗，每欄外框垂直置中；比賽列為左隊、40px 的 VS、右隊，不使用隊徽、Round 標題、圖例或上下疊卡。頁首中央是 ◆ 與 WORLDS 2026，其下是 `#19b8f0` 的水平漸層橫幅，寫 SWISS STAGE 與快照裡的目前輪次 ROUND N，試算不改這個輪次。頁面底是深藍夜景；強調藍 `#19b8f0`、試算金 `#f5c04a`、淘汰紅 `#e0566b`。工具列顯示 `fetchedAt`、試算場數與「清除試算」。晉級欄依 3-0、3-1、3-2 標成 1ST/2ND、3RD/4TH/5TH、6TH/7TH/8TH，晉級用強調藍、淘汰用淘汰紅。官方勝白字、敗半透明，試算勝 `#f5c04a`，系統配出的下一輪外框為 `#f5c04a` 虛線。點隊伍開右側單一面板，面板含戰績紀錄；已判的試算再按一次即取消。按下「換」後的兩下點擊只選隊伍。尺寸與禁止項以 `specs/advance-trial/spec.md` 為準。

50/50 只用於面板：由該隊目前戰績展開直到三勝或三敗的勝敗樹，每一未定系列賽乘上二分之一。已寫入的結果不再展開。

替代方案是用元件框架拆卡片。畫面會偏離單張轉播圖，因此不採用。

## Risks / Trade-offs

- [快照會過期] → 頁面標明 `fetchedAt`。要更新時重跑抓取腳本並替換 JSON，不在執行期自動更新。
- [隊徽先不做] → 比賽列只顯示種子與代號，不讀取隊伍圖片。
- [奇數池或官方臨時改配對規則] → 停止配對並標明，不發明重賽或跨池場次。
- [佇列互相覆蓋] → 面板標出被較晚走向蓋過的隊伍，避免靜默改寫。

## Migration Plan

新專案沒有舊資料。部署是放上靜態檔與 JSON 後執行 `node server.js`。退回時停掉該程序並移除這些檔案即可。
